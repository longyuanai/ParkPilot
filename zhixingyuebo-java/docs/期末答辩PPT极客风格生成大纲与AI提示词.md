# 03. 核心突破一：纯手写高性能动态代理连接池
## 解决高并发频繁 TCP 握手开销与连接泄漏
- 技术实现机制：
  - BlockingQueue + CAS 状态机线程安全管理；
  - 借助 java.lang.reflect.Proxy 动态代理物理 Connection；
- 拦截技术细节：
  - 拦截 close()：将物理断开优雅转化为无损归还空闲队列；
  - 拦截 isClosed() 与非法操作：连接归还后再次调用立即抛出安全异常；
  - 状态重置：归还前自动执行 rollback()、复位 autoCommit=true，清除脏连接污染；
  - 心跳探活：集成 isValid(1) 机制，自动剔除失效网络句柄。

## 四、答辩现场核心质询及应答话术秘籍

### Q1：为什么系统要自己手写动态代理连接池，而不直接用 HikariCP？
> **满分回答**：
> “第三方连接池虽然成熟，但在教学与底层技术探究场景下属于‘技术黑盒’。为了深入掌握 JVM 动态代理机制与 JDBC 网络连接复用原理，我采用 JDK 自带的 `Proxy` 拦截了物理 `Connection` 的 `close()` 方法，使其在调用时无损放回 `BlockingQueue` 空闲队列，同时配合 `AtomicInteger` 进行 CAS 状态并发控制。此外，手写连接池能与系统专为测试设计的‘随机沙箱测试库’以及 `ThreadLocal` 事务管理形成 100% 的精准受控契合，确保随测随毁时连接句柄彻底释放，杜绝连接泄漏。”

### Q2：高并发场景下，如何保证车主离场扣款和车位释放不会出现‘超卖’或‘单边账’？
> **满分回答**：
> “系统采用‘双重防御机制’：
> 1. **数据库层**：在扣减前使用 `SELECT ... FOR UPDATE` 排他悲观锁锁定单据与账户记录，将竞争串行化；
> 2. **事务原子边界**：在 Service 层利用 `DBUtil.beginTransaction()` 将‘扣减钱包’、‘写入资金只读流水’、‘更新车位为空闲’、‘回填停车单出场时间’绑定在同一个物理数据库事务中。只要任何一个步骤发生异常或余额不足，系统立即全盘 `rollbackTransaction()`，且道闸绝不抬杆，彻底杜绝单边账。”
