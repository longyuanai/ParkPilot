## 开场

各位老师好，我的项目是智行悦泊智慧停车与充电管理系统。它使用 Java SE、JDBC 和 MySQL，实现车位预约和进出场、停车月卡、充电与故障处理、钱包扣费及审计。我会展示停车扣款和月卡办理，再说明如何用同一事务保持账单、钱包和业务状态一致。

## 演示顺序

1. 运行 `demo.bat`，登录车主账号 `13800000001`，查看车主菜单、绑定车辆和钱包。`13800000003` 对应运维技师，`13800000004` 对应物业管理员。
2. 在车主菜单 5 为川A88888 办理离场。应收 4.00 元，钱包从 500.00 元变为 496.00 元。对照报告 TC-02 的 Navicat 查询，核对停车记录和对应流水。
3. 登录 `13800000002` 为川A66666 办理离场。固定跨日场景应收 80.00 元，车主余额为 50.00 元。对照 TC-03 中余额、在场记录和资金流水的前后查询结果。
4. 用 `13800000005` 演示川AD12345 停入 B-0201 后开桩。按 1.50 元每度结算 30.00 度，应付 45.00 元。TC-04 保留完整结算结果。
5. 结合 TC-05 展示 B-0202 的 E01 故障上报、技师认领、填写处置记录和消警。S-07 单独验证消警时原充电单待结算的处理。
6. 用 A-01 展示充电进度和自动结算。管理员还能导出 CSV 日报，B-01 校验了文件编码与跨日数据隔离。
7. 用 M-01 展示菜单 8。确认扣款后月卡增加 30 天。取消保留原有资产，连续两笔确认分别扣款 100.00 元，最终余额为 300.00 元。M-04 校验并发续费与日报月卡实收。

执行 `verify_tests.bat` 可重跑全量 43 项用例（涵盖核心 TC-01~09、高并发 F-01~08、安全防御 S-01~08、月卡机制 M-01~05、隔离演示 D-01~05 及架构优化 O-01~06）。`demo.bat` 每次创建新样例库，固定停车计费时点。从主菜单输入 0 退出时清理该库。

## 关键设计

- **角色与分层**。`User` 定义 `showMenu()`，三个子类提供各自菜单。表现层遵循单一职责（SRP），`ConsoleMenu` 充当前端控制器（Front Controller）分发路由，具体业务交互解耦为 `OwnerConsoleView`、`TechnicianConsoleView`、`AdminConsoleView`。Service 校验业务并管理事务，DAO 负责参数化 SQL。
- **同一事务**。`DBUtil.beginTransaction()` 关闭自动提交，用 `ThreadLocal<Connection>` 让同一线程中的 DAO 共用连接。成功后提交，异常时回滚并清理连接。停车扣费、车位释放、出场单和资金流水一起提交。
- **并发与权限**。先锁车辆并校验归属，再锁车位和相关订单。有效预约只允许预约人泊入。车主可组合筛选车位类型和区域。唯一索引限制同一车辆或同一车位仅有一条在场记录。
- **计费策略与开闭原则**。采用策略模式（`strategy/`），`FeeStrategyFactory` 动态管理 `ParkingFeeStrategy`、分时峰谷充电计费 `PeakValleyChargingFeeStrategy` 与超时占桩滞纳金 `StandardIdleFeeStrategy`（15分钟免费宽限期 + 0.5元/分 + 50元封顶）。金额和电量强制使用 `BigDecimal`。
- **原生动态代理连接池**。纯原生实现的 `SimpleConnectionPool`，基于 JDK 动态代理 `Proxy` 拦截 `Connection.close()` 实现自动归还复用，结合 `BlockingQueue`、CAS 原子计数器与 `isValid(1)` 探活，摆脱第三方连接池依赖。
- **独立月卡与欠费挂账闭环**。独立物理表 `tb_monthly_card` 记录历史台账；欠费时支持应急出场挂账（`pay_status=0`），充值后支持在线原子补缴状态机翻转（`pay_status=3`）。
- **故障与充电**。新能源车停入对应车位后才能开桩。故障把正在充电的订单转为中断待结，技师消警后仍由原订单占用设备。待结订单归档后按故障状态决定设备是否可用。
- **报表与模拟**。充电线程每两秒保存一次累计电量。余额不足时保留原值，充值后按原计量补结算。日报分别汇总实收和完成车次，免费离场计入车次。
