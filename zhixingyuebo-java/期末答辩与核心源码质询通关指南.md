## 开场

各位老师好，我的项目是智行悦泊智慧停车与充电管理系统。它使用 Java SE、JDBC 和 MySQL，实现车位预约和进出场、充电与故障处理、钱包扣费及审计。我会展示一次停车扣款和一次余额不足拦截，然后说明如何用同一事务保持账单、车位和钱包一致。

## 演示顺序

1. 在演示库登录车主账号 `13800000001`，查看车主菜单、绑定车辆和钱包。`13800000003` 对应运维技师，`13800000004` 对应物业管理员。
2. 用验收记录 TC-02 核对川A88888 的离场小票。停放 90 分钟，应收 4.00 元，钱包从 500.00 元变为 496.00 元。核对停车记录、车位状态和同一笔扣费流水。
3. 用 TC-03 展示余额不足。固定跨日场景的应收为 80.00 元，车主余额为 50.00 元。对照余额、在场记录和资金流水的前后查询结果。
4. 用 `13800000005` 演示川AD12345 停入 B-0201 后开桩。按 1.50 元每度结算 30.00 度，应付 45.00 元。TC-04 保留完整结算结果。
5. 结合 TC-05 展示 B-0202 的 E01 故障上报、技师认领、填写处置记录和消警。S-07 单独验证消警时原充电单待结算的处理。
6. 用 A-01 展示充电进度和自动结算。管理员还能导出 CSV 日报，B-01 校验了文件编码与跨日数据隔离。

执行 `verify_tests.bat` 可重跑 27 项。TC-02 和 TC-03 在随机测试库使用固定时点。初始化 SQL 中的演示记录按导入时间生成，现场手工演示的金额会随离场时刻变化。

## 关键设计

- **角色与分层**。`User` 定义 `showMenu()`，三个子类提供各自菜单。`ConsoleMenu` 负责交互，Service 校验业务并管理事务，DAO 负责参数化 SQL。
- **同一事务**。`DBUtil.beginTransaction()` 关闭自动提交，用 `ThreadLocal<Connection>` 让同一线程中的 DAO 共用连接。成功后提交，异常时回滚并清理连接。停车扣费、车位释放、出场单和资金流水一起提交。
- **并发与权限**。先锁车辆并校验归属，再锁车位和相关订单。有效预约只允许预约人泊入。数据库唯一索引限制同一车辆或同一车位仅有一条在场记录。八路并发抢同一车位的用例只产生一条成功记录。
- **计费**。金额和电量使用 `BigDecimal`。停车先扣除 30 分钟免费时长，再按园区自然日切分并向上取整小时，每日最高 50 元。管理员登记月卡到期时间，有效月卡免停车费并记录零金额流水。
- **故障与充电**。新能源车停入对应车位后才能开桩。故障把正在充电的订单转为中断待结，技师消警后仍由原订单占用设备。待结订单归档后按故障状态决定设备是否可用。
- **报表与模拟**。充电线程每两秒更新一次电量，达到目标后调用常规结算。`CsvExportUtil` 按结算日期汇总停车和充电金额，并写入 UTF-8 BOM 供表格软件识别。
